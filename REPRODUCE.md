# Reproducing our submission

This repository is the organisers' starter kit plus our pipeline in `solution/`. One command
regenerates our submission file from the provided match data.

## 1. Environment

Tested with **Python 3.12.4** on Windows 11.

```bash
pip install -r requirements-solution.txt
```

The versions are pinned exactly (numpy 1.26.4, pandas 2.2.2, scipy 1.13.1) because the file must be
regenerated byte-for-byte. Other versions may change floating-point results at decision thresholds.

## 2. Data

The match data is not in this repository (it is licensed for the competition only). Unpack the
bundle into `data/` exactly as described in [DATA.md](DATA.md):

```
data/tactical/BAR-ATH_tactical_atd.xml
data/tactical/BAR-ATH_tactical_atd.txt
data/tactical/BAR-ATH_tactical_smart_tagging.xml
```

Only these three tactical files are read. Or point `MTAH_DATA_DIR` at the folder holding the bundle.

## 3. Run

From the repository root:

```bash
python solution/make_submission.py --name <team_name>
python evaluation/validate_submission.py evaluation/results/<team_name>.csv
```

It takes about 15 seconds. It writes `evaluation/results/<team_name>.csv` (199,319 rows) and prints
summary statistics only. The first run also writes a parsed-tracking cache to `solution/cache/`;
it is gitignored and rebuilt automatically when the tracking file changes.

**Expected result:** the file we produced has SHA-256
`f0c0458f4ad4002a43e1bb44420951adab55ea45605acebfcc440fedc5db2b1a` with the environment above.
Two runs from an empty cache give the identical file.

## What we added to the starter kit

| File | What it does |
|---|---|
| `solution/make_submission.py` | The entry point: loads the data, runs the pipeline, writes and summarises the CSV. |
| `solution/pipeline.py` | The whole pipeline as one function, so every caller runs exactly the same steps. |
| `solution/atd.py` | Fast loader for the tracking data: converts positions to metres and re-indexes from the tracking's 1-based frame ids to 0-based video frames. Parses with pandas' C parser, with an exact per-group check and a slow tolerant fallback for irregular lines. |
| `solution/tags.py` | Reads the Smart Tagging XML into video-frame intervals; finds each half's kickoff from the kickoff tag and the ball leaving the centre spot; turns phase tags into a soft "which team has the ball" hint. |
| `solution/dead_ball.py` | Dead-ball detection. Combines ball off the pitch, ball lost at a line, ball parked at a line or corner, ball not seen moving, players walking, kickoff formation and set-piece tag windows into a per-frame score, then cleans it into stoppages (hysteresis, minimum durations, start each stoppage where play stopped, merge short uncontrolled live slivers). |
| `solution/possession.py` | Who has the ball while it is live: per-frame team evidence from how much closer the nearest home player is than the nearest away player, gated by distance and ball speed, then a two-state Viterbi decoder with a switch cost so a change of possession needs sustained control (touches and deflections do not count). |
| `solution/__init__.py` | Makes `solution` an importable package. |
| `requirements-solution.txt` | Pinned dependencies (above). |
| `.gitignore` (edited) | Also ignores the tracking cache (`solution/cache/`, `*.npz`, `*.npy`), which is a copy of the match data, and editor history snapshots (`.history/`). |

No file in `solution/` contains match data, labels, or numbers tied to specific frames of this match.
The public 5-minute ground truth is not read by the pipeline.
